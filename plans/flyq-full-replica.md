# FLYQ 全站复刻实施计划

## 1. 目标与成功标准

在现有 React 19 + Vite 8 + Tailwind CSS v4 空白项目中，完整复刻 `https://flyq.co.kr/#tab1` 的单页沉浸式展示体验：

- 保留原站“固定视口 + 顶部品牌区 + 六栏目标签 + 栏目内分页切换”的信息架构。
- 覆盖 6 个主栏目、共 16 个主画面：
  - 品牌：3 画面
  - 特化设计：2 画面
  - 区位环境：3 画面
  - 户型指南：5 画面
  - 社区：2 画面
  - 新闻与媒体：1 画面
- 实现桌面、宽屏、平板/手机竖屏的响应式布局。
- 复现原站的几何分割、黑色边框、柔和粉蓝绿黄灰色块、大字号排版、线框建筑/地图/平面图风格以及分步入场动效。
- 页面文案采用中英混排；品牌英文标题保留，说明性正文改为中文。
- 不使用或热链原站图片、视频、新闻、PDF、Logo 文件；所有视觉资源、视频和新闻均使用本地自制占位内容。
- 不引入后端、CMS、账户、持久化或第三方接口。

验收时，用户应能通过顶部六个标签、鼠标滚轮、键盘、点击箭头和移动端滑动浏览全部内容；刷新带 `#tab1` 至 `#tab6` 的地址时能进入对应栏目。

## 2. 已确认约束

- 项目当前只有空白 `src/App.tsx` 和 Tailwind 入口 `src/index.css`，无既有组件库或设计系统。
- 使用当前 React/Vite/Tailwind 技术栈，不启动新的开发服务器。
- 素材策略：完全本地占位，不下载目标站公开素材。
- 内容策略：中英混排。
- 外部内容策略：新闻、视频、PDF、电话和外部登记入口均改为本地模拟体验，不依赖原站、Vimeo、YouTube 或其他外部服务。

## 3. 文件与代码组织

### 3.1 `src/App.tsx`

作为应用状态与路由锚点入口，负责：

- 当前主栏目 `activeSection`。
- 各栏目当前画面索引 `slideBySection`。
- 户型/楼层子选项状态。
- 地图弹层、预约弹层、视频占位弹层状态。
- URL hash 的初始化、点击更新和 `hashchange` 同步。
- 统一的滚轮节流、键盘导航与触摸手势分发。

### 3.2 `src/data/siteContent.ts`

集中维护页面数据，避免把大量文字和户型参数硬编码进 JSX：

- 六个栏目标题、hash、主题色和画面数量。
- 品牌、建筑、区位、社区、新闻画面的中英文文案。
- 15 个 Premium Office 类型。
- 20 个 Section Office 类型。
- 6 个 Office Floor 楼层组选项。
- 4 个 Retail Floor 楼层组选项。
- 新闻卡片和媒体占位项。

户型数据至少包含：类型编号、总单元数、专有面积、合同面积、平面图变体标识。

### 3.3 `src/components/`

按职责拆分，避免单文件承载 16 个复杂画面：

- `SiteHeader.tsx`
  - 自制文字版 FLYQ 标志。
  - “预约登记”和“到访路线”按钮。
- `SectionTabs.tsx`
  - 六个交叠多边形标签。
  - 当前栏目高亮及移动端 3×2 排列。
- `Stage.tsx`
  - 固定比例内容舞台、过场容器、方向提示和公共几何线框。
- `SlideNavigation.tsx`
  - 上/下或左/右方向提示、当前序号和总数。
- `PlaceholderGraphic.tsx`
  - 统一生成建筑、地图、人物、社区、平面图等本地 SVG/CSS 占位图。
- `Modal.tsx`
  - 通用可访问弹层，支持焦点管理、Esc 关闭和遮罩关闭。
- `sections/BrandSection.tsx`
- `sections/ArchitectureSection.tsx`
- `sections/LocationSection.tsx`
- `sections/PlansSection.tsx`
- `sections/CommunitySection.tsx`
- `sections/MediaSection.tsx`
- `SiteFooter.tsx`

若实现过程中发现某个 section 仍过大，可仅在该 section 内继续拆分 `slides/` 子组件，不建立通用抽象来强行统一视觉差异较大的画面。

### 3.4 `src/index.css`

- 保留 `@import 'tailwindcss';` 在文件首行。
- 在 `@theme` 中定义复刻所需的颜色、字体族和动画时长变量。
- 在 `@layer base` 中设置页面高度、默认字体、背景色和 reduced-motion 行为。
- 在组件层或普通 CSS 中定义：
  - 多边形 tab 的 `clip-path`。
  - 舞台几何分割线。
  - 入场/退场动画。
  - 响应式尺寸和极端宽高比适配。
  - 自制 SVG/CSS 占位图的视觉规则。

## 4. 页面结构与画面实现

### 4.1 全局框架

- 页面使用 `100dvh`，主体不产生常规纵向长页面滚动。
- 桌面端：
  - 顶部约 12% 为 Logo 与操作入口。
  - 六标签横向交叠排列。
  - 内容舞台占据余下空间。
  - 页脚信息仅在新闻媒体画面中形成底部品牌带，避免挤压其他画面。
- 移动端：
  - 顶部 Logo 居中，操作按钮位于右上。
  - 六标签排列为 3 列 × 2 行。
  - 内容舞台使用竖向构图和可裁切的大字号标题。
  - 保留安全区内边距。

### 4.2 品牌 `#tab1`（3 画面）

1. **Flight to Quality / Work-Life**
   - 超大英文标题、中文副标题、人物飞行主题线稿占位图。
   - 标题逐行上移显现，连接线横向展开，人物图延迟进入。
2. **FLYQ Brand Definition**
   - 左侧定义文案，右侧四象限框架。
   - Office / Community / Retail / Stay 四个自制线性图标。
3. **Hyper Work Place**
   - 大标题、品牌标识区与建筑占位图区。
   - 采用不对称网格和黑色粗线分割。

### 4.3 特化设计 `#tab2`（2 画面）

1. **20 层网格地标**
   - 建筑线框/块面占位图。
   - 20F + B4、基地面积、总建筑面积、637 间办公空间四项数据。
2. **Hyper Work Place 空间构成**
   - Office / Retail / Stay / Community 四类功能块。
   - 用分层建筑剖面占位图表现复合空间。

### 4.4 区位环境 `#tab3`（3 画面）

1. **交通价值**
   - 自制抽象轨道地图。
   - 地铁 3 号线、GTX-A、客流与三大商务区指标。
2. **Location Value**
   - 地图占位图和“交通、文化、自然”三重基础设施说明。
3. **Eunpyeong Business District**
   - 区域节点图、EBD 说明和四项统计数据。

### 4.5 户型指南 `#tab4`（5 画面）

1. **四类入口总览**
   - Premium Office、Section Office、Office Floor、Retail Floor 四个可点击区域。
   - 点击后切换到对应画面，并保留返回总览入口。
2. **Premium Office Plan**
   - 15 个类型标签。
   - 显示总单元数、专有面积、合同面积。
   - 右侧用参数化 CSS/SVG 平面图占位图，随类型切换产生轻微形态变化。
3. **Section Office Plan**
   - 20 个类型标签。
   - 同样的数据卡与参数化平面图占位图。
4. **Office Floor Plan**
   - 4F、5–9F、10F、11–18F、19F、20F 六组选项。
   - 楼层用途图例和本地楼层平面占位图。
5. **Retail Floor Plan**
   - B1、1F、2F、3F 四组选项。
   - 商业设施图例和可打开的“放大查看”本地弹层。

在窄屏上，类型标签区允许自身横向滚动，但不得触发整个页面横向溢出。

### 4.6 社区 `#tab5`（2 画面）

1. **3F Community**
   - 社区层整体概览、自制人物/空间插画。
   - 23 个设施、约 1,956.92㎡ 等核心数据。
2. **Office Community**
   - 用 15 个主要设施卡片概括原站密集设施列表。
   - 保留 3rd Floor ISO / Community 的大画面结构与编号视觉。
   - 桌面使用分布式图标网格，移动端改为紧凑滚动网格。

### 4.7 新闻与媒体 `#tab6`（1 画面）

- 左侧 News：3–4 张本地静态新闻卡片，含日期、分类和标题。
- 右侧 Media：广告片/项目片两个本地标签。
- 视频区域显示自制封面与播放按钮；点击打开本地占位视频弹层，弹层内显示动效背景、标题、伪进度条和关闭按钮，不发起网络请求。
- 底部实现品牌信息带：
  - 三个合作方文字标识占位。
  - 本地“使用条款”弹层。
  - 本地展示联系电话文本，但不触发真实拨号。

## 5. 交互与状态流

### 5.1 主栏目切换

- 点击标签：
  1. 更新 `activeSection`。
  2. 将目标栏目画面重置为第 1 画面。
  3. 更新 URL hash 为 `#tabN`。
  4. 播放短暂淡出/滑入过场。
- 浏览器前进/后退通过 `hashchange` 正确同步。
- 无效 hash 回退到 `#tab1`。

### 5.2 栏目内画面切换

- 桌面滚轮：
  - 使用节流/锁定避免一次滚动跨越多个画面。
  - 向下进入下一画面，向上进入上一画面。
  - 到达边界时不循环。
- 键盘：
  - `ArrowDown` / `ArrowRight` / `PageDown`：下一画面。
  - `ArrowUp` / `ArrowLeft` / `PageUp`：上一画面。
  - `Home` / `End`：当前栏目首尾画面。
  - `Escape`：关闭最上层弹层。
- 移动端：
  - 记录 pointer/touch 起点和终点。
  - 达到阈值后切换画面。
  - 在户型标签横向滚动、弹层和内部可滚动区域中不抢占手势。
- 点击方向提示也能完成切换。

### 5.3 弹层

- “到访路线”：打开本地路线弹层，包含自制地图、地址占位和预约提示。
- “预约登记”：打开本地预约说明弹层，不提交数据。
- 户型放大、视频、使用条款均复用通用 Modal。
- 打开弹层时锁定背景交互；关闭后焦点回到触发按钮。

### 5.4 动效

- 每个画面使用 `key` 或状态 class 重新触发入场动画。
- 动效分三层：
  - 结构线和色块：先展开。
  - 标题和数据：依次上移显现。
  - 插画/平面图：最后淡入或轻微位移。
- 切换总时长控制在约 600–900ms。
- 遵循 `prefers-reduced-motion`：关闭位移、缩放和分步延迟，只保留即时淡入。

## 6. 视觉资产策略

- 不复制目标站的 Logo、插画、建筑图、地图、户型图或品牌 SVG。
- 使用以下本地方式建立统一占位视觉：
  - 文字版 FLYQ 标志。
  - React 内联 SVG 绘制人物轮廓、建筑网格、交通路线、楼层轮廓。
  - CSS `linear-gradient`、`clip-path` 和边框构造粉/蓝/绿/黄/灰几何块。
  - 平面图根据数据变体生成不同房间矩形、走道和方向标。
- 图标优先使用小型内联 SVG；不引入额外图标库。
- 字体使用系统无衬线字体栈，并优先覆盖韩文/中文可读字体：
  - 拉丁标题：Arial/Helvetica 类几何无衬线。
  - 中韩正文：`"Noto Sans CJK SC"`, `"Noto Sans KR"`, `"PingFang SC"`, `"Microsoft YaHei"`, sans-serif。

## 7. 响应式与边界情况

- 关键验证视口：
  - 1440×900 桌面
  - 1920×1080 宽屏
  - 1024×768 平板横屏
  - 768×1024 平板竖屏
  - 390×844 手机
- 使用宽高比媒体查询补充普通宽度断点，避免在矮屏桌面中内容溢出。
- 超大标题允许受控裁切，但正文、导航和关键数据必须完整可读。
- 户型密集标签在移动端使用局部横向滚动。
- `100dvh` 与安全区变量处理移动浏览器地址栏和刘海屏。
- 无 JavaScript 外部资源失败场景，因为所有内容均在本地。
- 确保任何单一状态下都不产生页面级横向滚动条。

## 8. 可访问性

- 所有交互元素使用真实 `button` 或语义链接。
- Tabs 使用 `role="tablist"`、`role="tab"`、`aria-selected` 和关联面板。
- 当前画面序号通过可见文本表达，不只依赖颜色。
- 占位图若纯装饰则 `aria-hidden="true"`；有信息意义时提供简短标签。
- Modal 使用 `role="dialog"`、`aria-modal="true"`、标题关联和焦点约束。
- 保证浅色块上的正文达到合理对比度。
- 键盘可以访问所有标签、户型选择器和弹层控件。

## 9. 实施顺序

1. 建立内容数据模型、全局主题变量和固定视口框架。
2. 实现 Header、六栏目 Tabs、Stage、画面导航和 hash 同步。
3. 实现统一滚轮、键盘和触摸导航。
4. 按顺序完成 Brand、Architecture、Location 三个信息型栏目。
5. 完成 Plans 栏目的四类子界面、35 个户型数据项和楼层选择器。
6. 完成 Community 和 Media 栏目。
7. 实现地图、预约、视频、条款与户型放大弹层。
8. 补齐入场动画、移动端构图、极端宽高比和 reduced-motion。
9. 格式化、构建并进行多视口手工验证。

## 10. 验证方案

### 自动检查

- 运行仓库规定的格式化命令：`pnpm format`。
- 运行生产构建：`pnpm build`。
- 若格式化修改了文件，再次运行 `pnpm build`，确保最终代码可构建。

### 功能检查

- 六个标签均能切换，hash 与当前栏目一致。
- 直接打开 `#tab1` 至 `#tab6` 均进入正确栏目。
- 每个栏目画面数与计划一致，总计 16 个主画面。
- 滚轮、方向键、点击箭头和手机滑动均能在边界内切换。
- 主栏目切换后目标栏目回到首画面。
- Premium 15 项、Section 20 项、Office Floor 6 项、Retail Floor 4 项均可选择并更新数据/图形。
- 地图、预约、视频、条款和放大查看弹层可打开、可用 Esc/关闭按钮退出。
- 页面不发起到原站、Vimeo、YouTube 或其他内容服务的请求。

### 视觉检查

- 使用已运行的开发服务器，在关键视口截图检查：
  - 标签交叠、主舞台比例和内容裁切。
  - 首屏大标题与人物占位图。
  - 建筑、地图、平面图和社区画面的几何分割一致性。
  - 移动端 3×2 标签与竖向构图。
- 检查页面级水平/垂直溢出、文字截断、焦点环和 reduced-motion。

## 11. 非目标

- 不复制或分发原站受保护的图片、Logo、视频、PDF 和新闻源。
- 不建立真实预约表单、客户数据库、拨号、地图导航或 CMS。
- 不追踪原站广告像素、分析脚本或 Cookie。
- 不实现原站后台新闻 iframe。
- 不保证占位插画与原图逐像素一致；复刻重点是布局、视觉语言、信息结构、画面数量和交互体验。
